# 演示模式（OpenHarmony 调测闭环）

> 目标：**10 分钟**内，用一份真实失败的 XTS 报告，把一个 MR 从"失败"演到"回归通过"。
> 本文件是现场 runbook：只照这里念，脚本细节见 `scripts/demo/README.md`。

## 一页看懂

- **真跑**：报告解析、分诊（模型推理）、设备部署修复库、OTA 包预检、单模块回归。
- **替身（必须明说）**：门禁构建（本地产物契约，`mode=demo-local`）、OTA 三证据（历史真 run 回放）。
- **观众分层**：管理者听"判断与证据"，研发听"命令与判定规则"。每条口播都是两句。

## 演出前准备

### D-1
1. 设备：目标板在线、系统版本与预置包一致（`param get const.product.software.version`）。
2. 包：`/home/cx/os/v6.1/out/ota_final/update.zip` 在；`ota_preflight.sh` 能过（≈19 秒）。
3. 修复件：`libace_compatible.z.so.patched` 在；记住当前设备库 sha256（用于对比）。
4. 令牌：设置页「GitLab 凭据」确认可读（`glab api --hostname 192.168.11.238 user` 返回 200）。
   **失效也能演**——MR 段自动切快照，但要说"记录件"。
5. 彩排 ≥2 次，把实测耗时填进下面的表格。

### 演出前 5 分钟
```bash
python3 scripts/demo/democtl.py preflight --case mr260   # 期望 0 FAIL
python3 scripts/demo/democtl.py start --case mr260 --lane a
```
投屏：左半屏终端（状态卡），右半屏设备镜像；关掉通知。

## 时间轴（lane a，目标 ≤10:00）

| 时间 | 阶段 | 来源 | 动作 |
| --- | --- | --- | --- |
| 0:00 | 开场 | — | `democtl start` 已跑过；念一句定位 |
| 0:30 | report | live | `summarize_report.py` 出表（648/644/**4**） |
| 1:50 | triage | live | 两簇根因 + 当场说分流 |
| 3:10 | fix | live | `deploy_fix.py`：推送→重启→sha256 |
| 5:10 | mr | live/recorded | MR 260 页面 / `glab api` |
| 5:50 | ci | local-staged | `gate_stage.py`（≈19s） |
| 6:30 | ota | live+recorded | 预检真跑 + 三证据 |
| 7:30 | regression | live | 回收后台结果（实测 ≈1:00，可更早回收） |
| 9:00 | done | live | 8/8 + 价值 |

**并行**：回归在 5:10 启动、后台跑，讲 MR/门禁/OTA 时它自己在跑。实测单模块回归
≈60 秒（16 例），比预算快，通常在 MR 段就能回收。

### 实测（2026-10-29 首次彩排，设备 8929）

| 段 | 实测 | 说明 |
| --- | --- | --- |
| report | 1s | `summarize_report.py` 直接出 648/644/4 |
| triage | <1s | 口播，无脚本 |
| fix | 0s（dry-run） | 真部署含 reboot ≈2:00，彩排未重启设备 |
| mr | <1s | 令牌 revoked，走状态快照（recorded） |
| ci | 19s | `gate_stage.py` 本地包 + 门禁契约 |
| ota | 16s | `ota_preflight.sh` 真跑 |
| regression | 60s | PASS 16/16（`ActsAACommandPrintSyncTest`） |

两个踩过的坑（已写进脚本）：
- 回归的 `--session-root` 落在 `~/.dsh/demo/...`（WSL 私有）时，`wslpath` 会转成 UNC，
  xdevice 枚举到 0 台设备；`regression_fast.py` 现在自动改到
  `<runner_dir>/reports/demo` 并打印注意项，证据 JSON 仍写回演示 run 目录。
- 共享 `config/user_config.xml` 的 `<sn>` 是别的板子，脚本会复制一份并只替换 `<sn>`。

### 裁员线（现场变慢时按序砍）
1. 跳过 triage 的 hilog 细节（只留两簇结论）——省 40 秒；
2. 跳过 OTA 三证据逐条念（只留勾选卡）——省 30 秒；
3. lane a → 不回归，改放历史结果并明说——省 2 分钟；
4. 全场切 lane c（纯回放）——6 分钟。

## 口播（照抄）

**开场**
- 管理：今天不演 PPT，演一条真记录：一份失败报告怎么变成一个可合并的 MR。
- 研发：8 个阶段，每段都有产物和来源标记；替身只有两处，我会点名。

**report**
- 管理：648 条用例，4 条失败。我们要看的不是"怎么变绿"，是"为什么红"。
- 研发：`summarize_report.py` 直接解析 `result/*.xml` 与 `module_run.log`，0.3 秒出表和失败用例名。

**triage**
- 管理：关键判断是分清产品问题和测试/环境问题——后者按规矩走豁免，不允许改用例。
- 研发：A 组横屏静置 + HAP 声明 portrait，启动即旋转，属测试侧；B 组日志链 `error:801` → 缺 SceneBoard，属产品/框架侧，可以修。

**fix**
- 管理：改动几十行：键盘避让基准从导航栏换成安全区底部，36px 偏差消失。
- 研发：备份原库→覆盖→重启→回连后比对 sha256，三步都过才算生效。

**mr**
- 管理：MR 本身很克制：标题说结论，正文 4 行以内。
- 研发：六维审查二轮，race P2 已修；minAPIVersion=23 是已知取舍，不藏。

**ci**
- 管理：真门禁要 40 分钟，这里用同形状产物契约替代，真实构建页我同时开着。
- 研发：`mode=demo-local` 写死，不伪造构建号、不调 Jenkins。

**ota**
- 管理：升级只认三件证据：包合法、升级器报 pass、设备真的启动完成。
- 研发：预检现场真跑 19 秒；升级器结果与启动标志来自 MR226 真实 run。

**regression**
- 管理：最后一步才是闭环：同一模块在修复后的设备上重跑，全通过才算过。
- 研发：复用受信任 phase3 实现，只跑一个模块；判定没放宽。

**收尾**
- 管理：从失败报告到可合并 MR，每一步都有证据、可复现、可审计。
- 研发：替身两处（门禁契约、OTA 回放），其余现场真跑；换用例只改 `cases/*.json`。

## 现场排障

| 现象 | 处理 |
| --- | --- |
| GitLab 401 revoked | MR 段用快照，口播"记录件" |
| 设备不回连 | 跳过 fix/回归，`stage ... --degraded`，切 lane c |
| 回归 `0 devices` | `regression_fast.py` 已自动覆盖 `<sn>`；仍失败就查 Windows `hdc list targets` |
| 回归超时 | 放历史结果（8941 修复版 8/8×2、全模块 929/929） |
| 脚本报错 | 不现场 debug，念 canned 输出继续 |
